# タスク設計書：Google認証による会員制機能

## タスクID
task-001

## タスクタイトル
Google認証による会員制機能

## ユーザーニーズ

### 背景
現在のLP（ランディングページ）は誰でもアクセス可能な公開サイトとなっていますが、以下のニーズに対応するため、会員制機能の実装が必要です：

1. **個人情報の保護**: 診断結果やユーザー情報を安全に管理したい
2. **継続的な利用**: 過去の診断結果を保存し、後から参照したい
3. **パーソナライズ**: ユーザーごとにカスタマイズされた体験を提供したい
4. **簡単な認証**: 複雑な登録手順を避け、Googleアカウントで簡単にログインしたい

### 解決すべき課題
- ユーザーが簡単にログインできる認証システム
- セキュアなセッション管理
- 会員専用ページへのアクセス制御
- ユーザー情報の管理と更新機能

## 仕様要件

### 機能要件

#### 1. 認証機能
- **NextAuth.js v5（Auth.js）を使用**
  - Google OAuth認証を実装
  - セッションベースのログイン状態管理
  - JWT方式のセッション管理

#### 2. 画面要件

##### 2.1 ログインページ（/auth/signin）
- **URL**: `/auth/signin`
- **機能**:
  - Googleログインボタンを表示
  - ログイン成功後は`/dashboard`にリダイレクト
  - 未認証ユーザーが保護されたページにアクセスした場合のリダイレクト先

##### 2.2 ダッシュボード（/dashboard）
- **URL**: `/dashboard`
- **認証**: 必須（未ログイン時は`/auth/signin`にリダイレクト）
- **表示内容**:
  - ユーザー名の表示
  - アバター画像の表示
  - ナビゲーションリンク（プロフィールページなど）

##### 2.3 プロフィールページ（/profile）
- **URL**: `/profile`
- **認証**: 必須（未ログイン時は`/auth/signin`にリダイレクト）
- **機能**:
  - ユーザー情報の表示（名前、メール、アバター）
  - プロフィール編集フォーム
  - 変更保存機能

#### 3. API要件

##### 3.1 NextAuth.js認証エンドポイント
- **URL**: `/api/auth/[...nextauth]`
- **メソッド**: GET
- **機能**: NextAuth.jsの認証処理を処理

##### 3.2 ユーザー情報取得API
- **URL**: `/api/user/profile`
- **メソッド**: GET
- **機能**: ログイン中のユーザー情報を取得

##### 3.3 プロフィール更新API
- **URL**: `/api/user/profile`
- **メソッド**: PUT
- **機能**: ユーザーのプロフィール情報を更新

#### 4. ミドルウェア要件
- `/dashboard`と`/profile`は認証必須
- 未ログインユーザーは`/auth/signin`にリダイレクト

### データモデル

#### User（NextAuth.jsデフォルト + 拡張）
```typescript
{
  _id: ObjectId,
  name: string,
  email: string,
  image: string, // GoogleアバターURL
  emailVerified: Date,
  createdAt: Date,
  updatedAt: Date
}
```

### 技術要件

#### 使用技術
- **NextAuth.js v5（Auth.js）**: 認証ライブラリ
- **MongoDB Adapter**: NextAuth.js用のMongoDBアダプター
- **Material-UI（MUI）**: UIコンポーネント
  - Button: ログインボタンなど
  - Card: ダッシュボード、プロフィール表示
  - Avatar: ユーザーアバター表示
  - TextField: プロフィール編集フォーム

#### 環境変数
- `GOOGLE_CLIENT_ID`: Google OAuth クライアントID
- `GOOGLE_CLIENT_SECRET`: Google OAuth クライアントシークレット
- `AUTH_SECRET`: NextAuth.js用のシークレットキー
- `MONGODB_URI`: MongoDB接続文字列

## 処理手順設計

### 1. 環境設定

#### 1.1 パッケージインストール
```bash
npm install next-auth@beta @auth/mongodb-adapter mongodb
npm install @mui/material @emotion/react @emotion/styled
```

#### 1.2 環境変数設定
`.env.local`ファイルに以下を追加：
```
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
AUTH_SECRET=your_auth_secret
MONGODB_URI=your_mongodb_uri
```

#### 1.3 Google OAuth設定
1. Google Cloud Consoleでプロジェクトを作成
2. OAuth 2.0認証情報を作成
3. 承認済みのリダイレクトURIに`http://localhost:3000/api/auth/callback/google`を追加

### 2. NextAuth.js設定

#### 2.1 認証設定ファイル作成
`app/api/auth/[...nextauth]/route.ts`を作成
- NextAuth.js v5の設定
- Googleプロバイダーの設定
- MongoDBアダプターの設定
- セッション設定（JWT方式）

### 3. ミドルウェア実装

#### 3.1 認証ミドルウェア作成
`middleware.ts`をルートに作成
- `/dashboard`と`/profile`へのアクセスを保護
- 未認証ユーザーを`/auth/signin`にリダイレクト

### 4. ページ実装

#### 4.1 ログインページ
`app/auth/signin/page.tsx`を作成
- Googleログインボタン（MUI Button使用）
- NextAuth.jsの`signIn`関数を使用

#### 4.2 ダッシュボードページ
`app/dashboard/page.tsx`を作成
- セッションからユーザー情報を取得
- ユーザー名・アバター表示（MUI Card, Avatar使用）
- ナビゲーションリンク

#### 4.3 プロフィールページ
`app/profile/page.tsx`を作成
- ユーザー情報表示（MUI Card使用）
- プロフィール編集フォーム（MUI TextField使用）
- 保存ボタン（MUI Button使用）

### 5. API実装

#### 5.1 ユーザー情報取得API
`app/api/user/profile/route.ts`を作成
- GET: セッションからユーザー情報を取得して返す

#### 5.2 プロフィール更新API
`app/api/user/profile/route.ts`にPUTメソッドを追加
- リクエストボディから更新情報を取得
- MongoDBでユーザー情報を更新
- 更新後の情報を返す

### 6. セッション管理

#### 6.1 セッション取得ヘルパー
`lib/auth.ts`を作成（必要に応じて）
- `getServerSession`を使用してセッションを取得するヘルパー関数

### 7. UIコンポーネント

#### 7.1 ログインボタンコンポーネント
必要に応じて`app/components/auth/GoogleSignInButton.tsx`を作成
- MUI Buttonを使用したGoogleログインボタン

#### 7.2 ユーザーアバターコンポーネント
必要に応じて`app/components/auth/UserAvatar.tsx`を作成
- MUI Avatarを使用したユーザーアバター表示

## 注意事項

1. **NextAuth.js v5（Auth.js）の使用**: v5はベータ版のため、最新のドキュメントを確認すること
2. **セキュリティ**: 環境変数は`.env.local`に保存し、Gitにコミットしないこと
3. **MongoDB接続**: MongoDBアダプターを使用するため、MongoDBの接続文字列が必要
4. **Google OAuth設定**: 本番環境では適切なリダイレクトURIを設定すること
