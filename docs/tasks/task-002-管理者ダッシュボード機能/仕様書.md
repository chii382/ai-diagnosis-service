# 仕様書：管理者ダッシュボード機能

## 1. 概要

### 1.1 機能概要
管理者ダッシュボード・権限管理・分析レポート機能

### 1.2 目的
AIキャリア診断サービスの運営管理者が、診断利用状況の把握、ユーザー管理、分析、エラー監視を行うための専用画面を提供する。

---

## 2. 画面仕様

### 2.1 管理者ダッシュボード（/admin）

| 項目 | 内容 |
|------|------|
| URL | `/admin` |
| 認証 | adminロール必須 |
| 本日の診断数 | 当日0時〜現在までの診断件数 |
| 総診断数 | 全期間の診断件数 |
| アクティブユーザー数 | usersコレクションの件数 |
| 最近の診断結果 | 直近5件の診断一覧（日時・サマリー） |
| システムステータス | DB接続状態、API応答時間 |
| クイックアクション | ユーザー管理、分析レポートへのリンク |

### 2.2 診断分析レポート（/admin/analytics）

| 項目 | 内容 |
|------|------|
| URL | `/admin/analytics` |
| 認証 | adminロール必須 |
| 診断数グラフ | 日別・週別・月別（recharts LineChart） |
| 人気キャリアパスTOP10 | BarChart または テーブル |
| 診断完了率 | 数値表示 |
| CSVエクスポート | 分析データのCSVダウンロード |

### 2.3 ユーザー管理（/admin/users）

| 項目 | 内容 |
|------|------|
| URL | `/admin/users` |
| 認証 | adminロール必須 |
| ユーザー一覧 | ページネーション（20件/ページ） |
| 検索・フィルタ | メール、名前、ロール |
| ロール変更 | admin ⇔ user の切り替え |
| 表示項目 | アバター、名前、メール、ロール、診断数、登録日 |

### 2.4 エラーログ監視（/admin/errors）

| 項目 | 内容 |
|------|------|
| URL | `/admin/errors` |
| 認証 | adminロール必須 |
| エラーログ一覧 | 日時、メッセージ、URL |
| Sentry連携 | SENTRY_DSN設定時に連携状況表示 |

## 3. API仕様

### 3.1 GET /api/admin/stats

管理者ダッシュボード用統計データを返す。

**認証**: adminロール必須

**レスポンス**:
```json
{
  "todayCount": 0,
  "totalCount": 0,
  "activeUserCount": 0,
  "recentDiagnoses": [],
  "dbStatus": "ok",
  "apiResponseTime": 5
}
```

### 3.2 GET /api/admin/users

ユーザー一覧を返す。

**認証**: adminロール必須

**クエリパラメータ**:
- `page`: ページ番号（1始まり）
- `search`: メール・名前で検索
- `role`: フィルタ（admin / user）

**レスポンス**:
```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "perPage": 20,
  "totalPages": 0
}
```

### 3.3 PATCH /api/admin/users/[id]

ユーザーのロールを変更する。

**認証**: adminロール必須

**リクエストボディ**:
```json
{ "role": "admin" }
```

### 3.4 GET /api/admin/analytics

分析データを返す。

**認証**: adminロール必須

**レスポンス**:
- dailyChart, weeklyChart, monthlyChart
- topCareers（人気キャリアパスTOP10）
- completionRate, totalDiagnoses

### 3.5 GET /api/admin/errors

エラーログ一覧を返す。

**認証**: adminロール必須

## 4. データモデル

### 4.1 User（usersコレクション）

| フィールド | 型 | 説明 |
|-----------|-----|------|
| _id | ObjectId | 主キー |
| name | string | 氏名 |
| email | string | メールアドレス |
| image | string \| null | アバターURL |
| emailVerified | Date \| null | メール認証日時 |
| **role** | 'admin' \| 'user' | 権限（追加） |
| createdAt | Date | 作成日時 |
| updatedAt | Date | 更新日時 |

## 5. 技術仕様

### 5.1 認証・認可

- NextAuth.js v5のセッションに`role`を追加
- ミドルウェアで`/admin`配下を保護（adminロール必須）
- 未認証: `/auth/signin`へリダイレクト
- 認証済みだがadmin以外: `/?adminDenied=1`へリダイレクト（LPでエラーダイアログ表示）

### 5.2 環境変数

| 変数名 | 説明 |
|--------|------|
| ADMIN_EMAILS | 初回admin付与用メール（カンマ区切り） |
| SENTRY_DSN | Sentryエラー監視用DSN |

### 5.3 使用技術

- MUI: Card, Chip, Tab, Avatar, Table, DataGrid
- recharts: LineChart, BarChart
- @sentry/nextjs: エラー監視

## 7. 管理者の初回設定

1. `.env.local`に`ADMIN_EMAILS=管理者のメールアドレス`を設定
2. そのメールでGoogleログイン（初回ログイン時にadminロール付与）
3. または、MongoDBのusersコレクションで該当ドキュメントの`role`を`admin`に手動更新
