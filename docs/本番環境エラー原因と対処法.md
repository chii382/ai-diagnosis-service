# 本番環境エラー原因と対処法

## エラーの原因

画像から確認できる問題点：

### 1. 環境変数が開発環境のみに設定されている
**問題**: すべての環境変数が「Development」タブにのみ設定されており、本番環境（Production）に設定されていません。

**影響を受ける環境変数**:
- `MONGODB_URI` - MongoDB接続不可
- `GOOGLE_CLIENT_ID` - Google認証不可
- `GOOGLE_CLIENT_SECRET` - Google認証不可
- `AUTH_SECRET` - NextAuth.jsセッション管理不可
- `AUTH_URL` - 認証URL設定なし
- `NEXTAUTH_URL` - NextAuth.jsのベースURL設定なし

### 2. 本番環境用のURL設定が不足
**問題**: `AUTH_URL`と`NEXTAUTH_URL`が`http://localhost:3000`のままです。

**必要な設定**:
- 本番環境のURL（例: `https://ai-diagnosis-service-virid.vercel.app`）

### 3. Google OAuthのリダイレクトURI設定不足
**問題**: Google Cloud Consoleで本番環境用のリダイレクトURIが設定されていない可能性があります。

**必要な設定**:
- 本番環境: `https://your-domain.com/api/auth/callback/google`

## 対処法

### ステップ1: 本番環境に環境変数を設定

デプロイプラットフォーム（Vercelなど）の環境変数設定画面で、**Production**環境に以下の環境変数を追加してください：

#### 必須環境変数

```env
# MongoDB接続文字列（開発環境と同じ値でOK）
MONGODB_URI=mongodb+srv://akirapapa_db_user:akirapapa@cluster0.yx71oyz.mongodb.net/?appName=Cluster0

# Google OAuth認証情報（開発環境と同じ値でOK）
GOOGLE_CLIENT_ID=1034055950152-s2fonhh8tj5dg7gab6m031bjtafipsve.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=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

# NextAuth.js設定（開発環境と同じ値でOK）
AUTH_SECRET=jozdqXva8ijeFv4kFPdXRgw+glTbotmiV4FFYrqfw88=

# 本番環境のURL（重要：本番環境のURLに変更）
NEXTAUTH_URL=https://ai-diagnosis-service-virid.vercel.app
AUTH_URL=https://ai-diagnosis-service-virid.vercel.app

# MongoDBデータベース名（オプション）
MONGODB_DB_NAME=auth
```

#### 設定時の注意点

1. **環境の選択**: 「Production」環境を選択して設定してください
2. **URLの変更**: `NEXTAUTH_URL`と`AUTH_URL`は本番環境のURLに変更してください
3. **シークレットの保護**: 環境変数は機密情報なので、GitHubにコミットしないでください（`.gitignore`で除外済み）

### ステップ2: Google Cloud ConsoleでリダイレクトURIを追加

1. [Google Cloud Console](https://console.cloud.google.com/)にアクセス
2. プロジェクトを選択
3. 「APIとサービス」→「認証情報」に移動
4. OAuth 2.0 クライアント IDを編集
5. 「承認済みのリダイレクト URI」に以下を追加：
   ```
   https://ai-diagnosis-service-virid.vercel.app/api/auth/callback/google
   ```
6. 保存

### ステップ3: デプロイプラットフォームでの設定確認

#### Vercelの場合

1. Vercelダッシュボードにログイン
2. プロジェクトを選択
3. 「Settings」→「Environment Variables」に移動
4. 各環境変数を追加：
   - **Environment**: Productionを選択
   - **Key**: 環境変数名（例: `GOOGLE_CLIENT_ID`）
   - **Value**: 環境変数の値
5. すべての環境変数を追加後、再デプロイを実行

### ステップ4: 再デプロイ

環境変数を設定した後、アプリケーションを再デプロイしてください：

```bash
# Vercelの場合、GitHubにプッシュすると自動デプロイされます
git commit --allow-empty -m "chore: trigger redeploy"
git push origin main
```

または、Vercelダッシュボードから「Redeploy」を実行してください。

## 確認方法

### 1. 環境変数の確認

デプロイプラットフォームの環境変数設定画面で、以下を確認：
- [ ] Production環境にすべての環境変数が設定されている
- [ ] `NEXTAUTH_URL`が本番環境のURLになっている
- [ ] `AUTH_URL`が本番環境のURLになっている

### 2. Google OAuth設定の確認

Google Cloud Consoleで以下を確認：
- [ ] 本番環境のリダイレクトURIが追加されている
- [ ] OAuth同意画面が設定されている

### 3. アプリケーションの動作確認

本番環境で以下を確認：
- [ ] ログインページが表示される
- [ ] Googleログインボタンが動作する
- [ ] 認証後にダッシュボードにリダイレクトされる
- [ ] セッションが維持される

## よくあるエラーと対処法

### エラー1: "AUTH_SECRET is not set"
**原因**: `AUTH_SECRET`環境変数が設定されていない
**対処**: Production環境に`AUTH_SECRET`を設定

### エラー2: "Invalid redirect URI"
**原因**: Google OAuthのリダイレクトURIが設定されていない
**対処**: Google Cloud Consoleで本番環境のリダイレクトURIを追加

### エラー3: "MongoDB connection failed"
**原因**: `MONGODB_URI`が設定されていない、または接続文字列が間違っている
**対処**: Production環境に`MONGODB_URI`を設定、MongoDB AtlasのIPホワイトリストを確認

### エラー4: "NEXTAUTH_URL is not set"
**原因**: `NEXTAUTH_URL`が設定されていない、または`http://localhost:3000`のまま
**対処**: Production環境に本番URLを設定

## まとめ

本番環境でエラーが発生している主な原因は、**環境変数が開発環境のみに設定されている**ことです。

**解決手順**:
1. ✅ Production環境にすべての環境変数を設定
2. ✅ `NEXTAUTH_URL`と`AUTH_URL`を本番URLに変更
3. ✅ Google Cloud Consoleで本番環境のリダイレクトURIを追加
4. ✅ アプリケーションを再デプロイ

これらの設定を行うことで、本番環境でのエラーが解消されるはずです。
