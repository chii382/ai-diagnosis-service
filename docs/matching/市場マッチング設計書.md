# 市場マッチング設計書

診断分析レポートで、AIキャリア診断の結果と市場における募集人材とのマッチング状況を可視化する機能の設計書です。

---

## 1. 概要

### 1.1 目的

- 診断を受けたユーザー群の「向いている業種・職種」と、市場で実際に募集されている業種・職種を比較する
- マッチングの過不足（需要 vs 供給イメージ）を分かりやすく表示し、管理者の意思決定を支援する

### 1.2 対象画面

- **診断分析レポート**（`/admin/analytics`）

### 1.3 想定ユースケース

- 管理者が診断結果の傾向を把握し、市場ニーズとの整合性を確認する
- 求人市場の傾向と診断ユーザーの適性傾向のギャップを可視化する

---

## 2. データ構造

### 2.1 診断分析側（現有データ）

| カテゴリ | データソース | 形式 | 備考 |
|----------|--------------|------|------|
| 向いている業種 | `aptitudeScores.業種` | `Array<{name, value}>` | 診断結果から集計 |
| 向いている職種 | `aptitudeScores.職種` | `Array<{name, value}>` | 診断結果から集計 |
| 年代別 | ユーザープロフィール `ageGroup` | `Array<{name, value}>` | 20未満、20代、30代… |
| 現状の業種 | ユーザープロフィール `industry` | `Array<{name, value}>` | |
| 現状の職種 | ユーザープロフィール `jobType` | `Array<{name, value}>` | |
| 性別 | ユーザープロフィール `gender` | （未集計） | 追加実装が必要 |

### 2.2 市場データ（取得対象）

AI により取得・生成する想定の市場募集人材データ：

| 項目 | 説明 | データ形式 |
|------|------|------------|
| 業種別需要 | 市場で募集が多い業種とその割合 | `Array<{name, value}>` |
| 職種別需要 | 市場で募集が多い職種とその割合 | `Array<{name, value}>` |
| 年代別需要 | 募集で求められる年齢層の傾向 | `Array<{name, value}>` |
| 性別需要 | 募集で性別指定がある場合の傾向 | `Array<{name, value}>` |

## 3. AI による市場データ取得

### 3.1 アプローチ

**オプションA: AI プロンプトで構造化データを生成**

- Anthropic API を用い、日本の求人市場の傾向に基づく「推定需要分布」を JSON 形式で返す
- 業種・職種・年代・性別の需要割合を、診断システムの語彙（業種・職種リスト）に揃えて返却
- メリット: 外部 API 不要、語彙の統一が容易
- デメリット: 実データではなく推論ベース

**オプションB: 外部求人 API を利用（将来検討）**

- Indeed、doda、リクナビ等の求人 API があれば実データを取得
- メリット: 実データに基づく分析
- デメリット: API キー・契約・料金・語彙の正規化が必要

**推奨: まずはオプションAで実装し、将来オプションBを検討**

### 3.2 AI プロンプト設計（案）

```
あなたは日本の求人市場の専門家です。
現在の日本における求人・募集の傾向を踏まえ、以下の形式で需要分布を返してください。
診断システムで使用している業種・職種の語彙に合わせてください。

【出力形式】JSON のみを返すこと
{
  "byIndustry": [ {"name": "IT・テクノロジー", "value": 25}, ... ],
  "byJobType": [ {"name": "エンジニア", "value": 20}, ... ],
  "byAgeGroup": [ {"name": "20代", "value": 35}, {"name": "30代", "value": 40}, ... ],
  "byGender": [ {"name": "指定なし", "value": 90}, {"name": "男性", "value": 5}, {"name": "女性", "value": 5} ]
}

※ value は相対的な需要割合（合計100になる想定）
※ 業種・職種は診断の aptitudeScores で使われる語彙と一致させること
※ データは直近1〜2年の傾向を反映した推定値とする
```

### 3.3 取得タイミング

| 方式 | 説明 |
|------|------|
| レポート表示時 | 毎回 AI を呼び、市場データを取得してマッチング計算 |
| 定期バッチ | 日次/週次で AI を呼び、結果を DB やキャッシュに保存し、レポートではキャッシュを参照 |
| 手動更新 | 管理者が「市場データ更新」ボタンで取得し、一定期間キャッシュ |

**推奨**: まずは「レポート表示時」で実装し、負荷が高ければキャッシュ導入

## 4. マッチングロジック

### 4.1 マッチング指標

| 指標 | 計算方法 | 表示イメージ |
|------|----------|--------------|
| 業種マッチ度 | 診断TOP業種と市場TOP業種の一致度・相関 | ヒートマップ / バー比較 |
| 職種マッチ度 | 診断TOP職種と市場TOP職種の一致度・相関 | 同上 |
| 年代マッチ度 | 診断ユーザー年代分布と市場需要年代分布の一致度 | 同上 |
| ギャップ分析 | 市場需要は高いが診断ユーザーが少ない領域（供給不足） | リスト表示 |

### 4.2 マッチング計算（案）

1. **正規化**: 診断側・市場側それぞれの分布を 0〜100 の割合に正規化
2. **共通語彙でマッピング**: 同じ業種名・職種名で紐付け。完全一致しない場合は類似語のマッピングテーブルを用意
3. **スコア算出**:
   - 各項目（業種/職種等）ごとに、診断分布と市場分布の差の絶対値を合計し、100から引いた値を「マッチ度」とする
   - または、コサイン類似度や相関係数を使用

### 4.3 語彙の統一

診断結果の業種・職種名は AI が動的に生成するため、市場データと完全一致しない場合がある。

**対応案**:

- AI プロンプトで「診断システムで使用される業種・職種の代表例」を渡し、同じ語彙で返すよう指示
- マッチング時に「業種・職種マッピングテーブル」で正規化（例: 「IT」「IT・テクノロジー」→「IT・テクノロジー」）
- 完全一致しない項目は「その他」として集約

## 5. UI 設計

### 5.1 表示項目

1. **マッチングサマリーカード**
   - 業種マッチ度: XX%
   - 職種マッチ度: XX%
   - 年代マッチ度: XX%
   - 全体マッチ度（加重平均）: XX%

2. **業種マッチング比較グラフ**
   - 横軸: 業種名
   - 診断結果（青系）と市場需要（オレンジ系）を並列バーチャートで表示
   - または、積み上げバーで供給 vs 需要を表現

3. **職種マッチング比較グラフ**
   - 同上

4. **ギャップ分析**
   - 「市場では需要が高いが、診断ユーザーの適性では少ない」業種・職種をリスト表示
   - 逆に「診断ユーザーに多く向いているが、市場需要は相対的に低い」項目も表示

### 5.2 画面レイアウト（案）

```
[診断トレンド]  （既存）
[診断結果グラフ] （既存）

★ 新規: [市場マッチング]
  - マッチングサマリー（4つの円グラフ or 数値カード）
  - 業種マッチング比較（バーチャート）
  - 職種マッチング比較（バーチャート）
  - ギャップ分析（テーブル or リスト）

[ユーザー属性]  （既存）
```

## 6. 技術実装方針

### 6.1 API 構成

| API | 役割 |
|-----|------|
| `GET /api/admin/analytics` | 既存。診断集計データを返す |
| `GET /api/admin/analytics/market`（新規） | 市場データを AI から取得して返す。または analytics に統合 |
| マッチング計算 | フロントエンド or バックエンドで実装 |

### 6.2 フロー

1. 診断分析画面を表示
2. 既存 `/api/admin/analytics` で診断集計を取得
3. `GET /api/admin/analytics/market` で市場データを取得（AI 呼び出し）
4. フロントエンド（または専用 API）でマッチング計算
5. マッチングサマリー・比較グラフ・ギャップ分析を描画

### 6.3 性別の扱い

- 現状、 analytics API では `gender` を集計していない
- 市場マッチングに性別を含める場合、`/api/admin/analytics` に `byGender` を追加
- ユーザープロフィールの `gender` を集計する処理を実装

## 8. 注意事項・リスク

- **AI の出力精度**: 市場データは AI の推論であり、実測値ではない。UI 上で「推定値」「参考」である旨を明記する
- **語彙の揺れ**: 診断の業種・職種名と市場データの語彙が一致しない場合、マッピングテーブルで吸収する必要がある
- **API コスト**: レポート表示のたびに AI を呼ぶとコスト増。キャッシュ導入を検討
- **性別・年齢の取り扱い**: 採用における年齢・性別の取扱いは法的・倫理的に配慮が必要。市場データとしては「募集傾向の参考」として表示し、差別的利用を避ける
