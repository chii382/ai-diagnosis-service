# Stripe ダッシュボード：商品設計の整理（Lesson5-1 前提）

キャリア診断サービス（Next.js + TypeScript + MongoDB）向けに、Stripe 上で **Product** と **Price** をどう置くか、ダッシュボードでの作業手順、サブスクリプションの考え方をまとめたメモです。

---

## 1. Product と Price の整理

### 1.1 今すぐ作る想定（月額サブスクリプション）

**アプリで提供する有料機能（Lesson5-1 の整理）**

| 内容 |
|------|
| 詳細キャリアロードマップ |
| 診断履歴の保存 |
| PDF ダウンロード |

これらをひとまとめにした **1 つの Product** と、その売り方として **1 つの Price（月額）** を用意するのがシンプルです。

#### Product（商品）の案

| 項目 | 入力の例・案 |
|------|----------------|
| **名前（Name）** | `プロプラン` または `Career Diagnosis Pro`（英語は API やメールでそのまま出ることがあるので、社内用と表示用を分けたい場合はメモ欄に書く） |
| **説明文（Description）** | 例：「AI による詳細キャリアロードマップ、診断履歴の保存・比較、結果の PDF ダウンロードが利用できる月額プランです。」 |

説明文は **お客様向けの請求書・カスタマーポータル** に表示されることがあるので、短く分かりやすく書くとよいです。

#### Price（価格）の案

| 項目 | 値の例 |
|------|--------|
| **金額** | `980`（円） |
| **通貨** | `JPY`（日本円） |
| **請求モード** | 定期課金（Recurring） |
| **請求間隔** | 毎月（Monthly） |

Stripe では **Product が「何を売るか」**、**Price が「いくら・どの周期で請求するか」** です。同じ Product に、後から「年額用の別 Price」を足すこともできます。

---

### 1.2 将来、追加するかもしれない Price（参考）

まだダッシュボードで作らなくてよい **候補** として覚えておくとよいものです。

| 種類 | 目的のイメージ | 設定のイメージ |
|------|----------------|----------------|
| **年額プラン** | 月額より安く見せて継続率を上げる | 同じ Product に、Recurring・**Yearly**・金額は例：年 9,800 円 など |
| **買い切り（一回払い）** | サブスクに抵抗があるユーザー向け | **別 Product** にするか、同じ Product に **One-time** の Price を追加（アプリ側で「どの Price を選ぶか」分岐が必要） |
| **クーポン・割引** | キャンペーン | Product ではなく **Coupon / Promotion Code** で割引率や期間を設定することが多い |

**注意:** 年額と月額を同じ Product に並べる場合、**アプリと Webhook で「どの Price ID か」で状態を判別**する設計が必要です。

## 2. ダッシュボード操作チェックリスト

### 2.1 テストモードの確認手順

| 手順 | やること |
|------|----------|
| 1 | Stripe にログインする |
| 2 | 画面左上（または設定付近）の **「テストモード」スイッチが ON** になっていることを確認する |
| 3 | **「テスト用の API キー」**（`pk_test_...` / `sk_test_...`）をコピーし、開発環境の `.env` に貼る（本番の `pk_live_` とは別管理） |

テストモードで作った Product / Price の ID は **`price_...` も test 用**です。本番用を作るときは **ライブモードに切り替えて** から、もう一度 Product / Price を作成します。

---

### 2.2 Product 作成時の入力項目と値（例）

ダッシュボード：**商品カタログ → 商品を追加**（表記は英語 UI の場合は *Products → Add product*）。

| 入力項目 | 入れる値の例 |
|----------|----------------|
| 名前 | `プロプラン` |
| 説明 | `詳細キャリアロードマップ、診断履歴の保存、PDF ダウンロードが利用できる月額プラン。` |
| （任意）画像 | LP のロゴなど |

初めてなら **説明は後から編集可能**なので、短くても問題ありません。

---

### 2.3 Price 作成時の入力項目と値（例）

Product 作成画面で一緒に Price を付けられる場合と、あとから **「価格を追加」** する場合があります。

| 入力項目 | 入れる値の例 |
|----------|----------------|
| 価格モデル | **標準価格**（通常はこれ） |
| 金額 | `980` |
| 通貨 | `JPY` |
| 請求方法 | **定期的**（Recurring） |
| 請求間隔 | **毎月**（Monthly） |

税込／税抜の扱いは国・事業形態によるため、会計担当の方針に合わせるか、Stripe Tax を使うかは別途決めるとよいです。

---

### 2.4 Price ID を控える手順

アプリの環境変数（例：`STRIPE_PRICE_ID_PRO_MONTHLY`）に **Price の ID** を入れて使うことが多いです。

| 手順 | やること |
|------|----------|
| 1 | テストモードのまま、作成した **Product** を開く |
| 2 | 紐づく **価格（Price）** の一覧から、月額 980 円の行を選ぶ |
| 3 | **Price ID**（`price_xxxxxxxx` 形式）をコピーする |
| 4 | パスワードマネージャーや `.env.example`（Git にコミットする場合はダミー）にメモする |

**本番用**の Price ID は、ライブモードで同様に作成し、**別の環境変数**（例：Vercel の Production）に入れます。テストと本番で ID が混ざると課金事故の原因になるので注意します。

## 3. サブスクリプション設計

### 3.1 無料トライアル期間を設ける場合

| やり方 | 説明 |
|--------|------|
| **Checkout Session を作るコード側** | `subscription_data: { trial_period_days: 7 }` のように **日数を指定**する方法がよく使われます |
| **Price 側のデフォルト** | Price に「試用期間」を付けることもできますが、**アプリごとに試用日数を変えたい**なら Checkout のパラメータで揃えると分かりやすいです |

トライアル中は **課金は発生せず**、期間終了後に最初の請求が走ります。  
「トライアル中もプロ機能を使える」かどうかは **アプリ側の判定**（Stripe の Subscription ステータスが `trialing` かどうか等）で制御します。

---

### 3.2 解約時の挙動（即時停止 vs 期間終了まで使える）

| パターン | 意味 | Stripe でのイメージ |
|----------|------|---------------------|
| **期間終了まで利用可能** | いま支払った分の期間が終わるまでプロ機能を使える | **解約＝「次回以降の更新を止める」**（多くの SaaS でこちら） |
| **即日停止** | 解約した瞬間にプロ機能を止める | アプリ側で即座に権限を落とす。請求済み期間の返金ルールは別途検討 |

Stripe のサブスクリプションを **キャンセル**するとき、

- **`cancel_at_period_end = true`** にすると「**現在の請求期間の終わりで止まる**」形にしやすいです。
- 即時に止めたい場合は、**キャンセル方法とアプリの権限ロジック**をセットで決めます。

FAQ や利用規約に「解約後はいつまで使えるか」を書いておくとトラブルが減ります。

---

### 3.3 将来のアップグレード／ダウングレードパスの設計（参考）

今は **プロプラン 1 種類**でも、将来プランが増える前提で考え方だけ整理します。

| 考え方 | 内容 |
|--------|------|
| **アップグレード** | 上位の Price に切り替える。**Stripe の Subscription を更新**し、`proration`（日割り）で差額を取るかどうかを API で指定できる |
| **ダウングレード** | 下位プランへ変更。**次の更新日から反映**にすると実装が簡単なことが多い |
| **おすすめの運用** | 複数 Price を同じ Product に並べるか、**プランごとに Product を分ける**かはチームで統一ルールを決める |

**Customer Portal（顧客ポータル）** を有効にすると、ユーザー自身で「プラン変更・支払い方法・解約」に進めるよう設定できます。Lesson5 の後半で実装するときの選択肢になります。
